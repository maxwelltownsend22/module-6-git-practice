# Guide Plan

## Topic

A practical Git and GitHub workflow for an individual developer, from cloning a repository through committing, pushing, reviewing a pull request, and resolving a merge conflict.

## Audience

Beginning programmers who know how to edit project files and want a repeatable way to track their work and publish changes on GitHub.

## Goals

- Explain what the key Git commands do in a typical task.
- Show how a feature branch and pull request fit into a repository workflow.
- Give a concrete process for creating and resolving an overlapping-edit conflict.
- Help readers inspect their commits and compare changes.

## Planned Sections

1. Clone a repository and check its remote and branch.
2. Create a feature branch and inspect local changes.
3. Stage, review, commit, and push focused changes.
4. Open, self-review, and merge a pull request linked to an Issue.
5. Reproduce and resolve a merge conflict between two branches.
6. Inspect commit history and project activity.

## Completion Checks

- Commands are shown in runnable code blocks and use consistent example names.
- The conflict walkthrough makes overlapping edits and removes all conflict markers before committing.
- The README includes a clear project overview and a screencast link once the recording is complete.
